# Module Config — Flow Map

## Install Flow

| Flow | Trigger | Key Functions | Decision Points | Outcome |
|------|---------|---------------|-----------------|---------|
| Fresh install | Admin clicks "Install" in back office | `razorpay.php:install()` -> `registerHook()` | DP1: parent::install() must succeed | Table created, 4 hooks registered |
| Table already exists | Re-install or DB not cleaned | `razorpay.php:install()` (CREATE TABLE IF NOT EXISTS) | IF NOT EXISTS guard | Silent no-op on table, hooks re-registered |

**Decision Points:**
- **DP1: No config defaults written on install** — `install()` creates the DB table and registers hooks but writes zero `Configuration::updateValue()` calls. All 8 config keys are absent until admin saves the form. Why: PrestaShop convention expects modules to have no config until configured; avoids stale placeholder values being used by checkout.

Hooks registered: `header`, `orderConfirmation`, `paymentOptions`, `paymentReturn`.

## Admin Save Flow (getContent / _postProcess)

| Flow | Trigger | Key Functions | Decision Points | Outcome |
|------|---------|---------------|-----------------|---------|
| Valid save | Admin submits form with KEY_ID + KEY_SECRET filled | `razorpay.php:getContent()` -> `_postValidation()` -> `_postProcess()` -> `autoEnableWebhook()` | DP1: empty key check; DP2: webhook gate | 8 keys persisted, webhook registered |
| Validation error | KEY_ID or KEY_SECRET empty | `razorpay.php:getContent()` -> `_postValidation()` | DP1 | Error displayed, `_postProcess()` skipped |
| Page load (no submit) | Admin opens config page | `razorpay.php:getContent()` -> `_displayForm()` | btnSubmit absent | Form rendered with current values |

**Decision Points:**
- **DP1: Required-field check** — `_postValidation()` blocks save if `KEY_ID` or `KEY_SECRET` is empty string (`empty()`). Applies only when `btnSubmit` is set. No format/prefix validation on the key values themselves.
- **DP2: ENABLE_RAZORPAY_WEBHOOK hardcoded to true on every save** — `_postProcess()` always calls `Configuration::updateValue('ENABLE_RAZORPAY_WEBHOOK', true)` regardless of form input, then `autoEnableWebhook()` may override it to `'off'` if localhost is detected or to `'on'` after successful registration. There is no UI toggle to disable webhooks; they are always attempted.

Config keys written by `_postProcess()` (8 total):
`RAZORPAY_KEY_ID`, `RAZORPAY_KEY_SECRET`, `RAZORPAY_PAYMENT_ACTION`, `ENABLE_RAZORPAY_WEBHOOK`, `RAZORPAY_WEBHOOK_EVENTS`, `RAZORPAY_WEBHOOK_WAIT_TIME`, `RAZORPAY_WEBHOOK_SECRET` (via autoEnableWebhook), `RAZORPAY_WEBHOOK_LAST_VERIFY` (via autoEnableWebhook).

## autoEnableWebhook Flow

| Flow | Trigger | Key Functions | Decision Points | Outcome |
|------|---------|---------------|-----------------|---------|
| Public host, webhook not found | Called from `_postProcess()` | `razorpay.php:autoEnableWebhook()` -> `webhookAPI('GET')` paginated loop -> `webhookAPI('POST')` | DP1: IP check; DP2: URL match in page loop; DP3: POST vs PUT | New webhook created, LAST_VERIFY written |
| Public host, webhook URL already exists | Same trigger | `razorpay.php:autoEnableWebhook()` -> paginated GET -> `webhookAPI('PUT')` | DP2: URL match found | Existing webhook updated (secret refreshed), LAST_VERIFY written |
| Private/localhost IP | Same trigger | `razorpay.php:autoEnableWebhook()` | DP1: filter fails | ENABLE_RAZORPAY_WEBHOOK set to `'off'`, early return, no API calls |

**Decision Points:**
- **DP1: Private IP gate** — `gethostbyname(domain)` result is checked with `FILTER_VALIDATE_IP, FILTER_FLAG_IPV4 | FILTER_FLAG_NO_PRIV_RANGE | FILTER_FLAG_NO_RES_RANGE`. Fails for localhost, 192.168.x.x, 10.x.x.x, 172.16-31.x.x, and reserved ranges. On failure, webhook is disabled silently.
- **DP2: URL match is exact string equality** — `$value['url'] === $webhookUrl` — the URL is generated by PS link helper and must match exactly what Razorpay has on record.
- **DP3: POST vs PUT branch** — if any webhook in the paginated list matches the URL, PUT is used to update it (preserving webhook ID). If none match across all pages, POST creates a new one.

Pagination: fetches 10 webhooks per page (`count=10`), increments `skip` by 10. Loop continues while `$webhook['count'] === $count` (i.e., exactly 10 returned = more pages may exist).

Note: There is **no 24h TTL gate** inside `autoEnableWebhook()` itself. The function runs unconditionally every time admin saves settings. `RAZORPAY_WEBHOOK_LAST_VERIFY` is written after success but is not read back to throttle calls. The TTL guard (if any) would need to be implemented in the caller — it is not present in `_postProcess()` either.

## hookHeader Flow

| Flow | Trigger | Key Functions | Decision Points | Outcome |
|------|---------|---------------|-----------------|---------|
| Checkout page load | Any page request where `controller == "order"` | `razorpay.php:hookHeader()` | DP1: controller check | CDN JS + local script.js registered; JS vars injected |
| Non-checkout page | Any other controller | `razorpay.php:hookHeader()` | DP1 fails | No scripts registered, early return |

**Decision Points:**
- **DP1: Controller filter** — only fires when `Tools::getValue('controller') == "order"`. This targets the PS 1.7+ one-page checkout. Other page types (cart, CMS, product) do not load Razorpay JS.
- **Amount pre-calculation** — cart total is multiplied by 100 and formatted as integer string (`number_format(..., 0, "", "")`). This amount is passed to the browser; the `order` controller re-fetches and validates it server-side before creating the Razorpay order.
- **rzp_order_id injected as empty string** — `$rzp_order_id = ""` is hardcoded. The actual Razorpay order ID is fetched asynchronously by `script.js` hitting the `order` controller before the checkout form renders.

## Uninstall Flow

| Flow | Trigger | Key Functions | Decision Points | Outcome |
|------|---------|---------------|-----------------|---------|
| Clean uninstall | Admin clicks "Uninstall" | `razorpay.php:uninstall()` -> `parent::uninstall()` | DP1: missing key | 7 config keys deleted, table dropped |

**Decision Points:**
- **DP1: RAZORPAY_WEBHOOK_LAST_VERIFY is NOT deleted** — `uninstall()` calls `deleteByName` for 7 keys but omits `RAZORPAY_WEBHOOK_LAST_VERIFY`. If the module is reinstalled, this stale timestamp remains in the PS configuration table. Since `autoEnableWebhook()` does not check this value before running, it has no functional impact today, but the orphaned row persists.

Keys deleted on uninstall: `RAZORPAY_KEY_ID`, `RAZORPAY_KEY_SECRET`, `RAZORPAY_PAYMENT_ACTION`, `ENABLE_RAZORPAY_WEBHOOK`, `RAZORPAY_WEBHOOK_EVENTS`, `RAZORPAY_WEBHOOK_SECRET`, `RAZORPAY_WEBHOOK_WAIT_TIME`.

Key NOT deleted: `RAZORPAY_WEBHOOK_LAST_VERIFY`.
